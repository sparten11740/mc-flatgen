# F23 Port to 26.1 (v2)

Milestone: v2 · Release: v2 · Status: doing · Depends on: F20

## Why

26.1 is the second release target: NeoForge and Fabric on Minecraft 26.1.

## Acceptance criteria

- [x] Nodes `26.1-neoforge` and `26.1-fabric` (Minecraft 26.1.2, Java 25, unobfuscated: no Parchment, plain Loom
  through loom-back-compat), with the versions Blockpilot's nodes use as the starting point.
- [x] Version tree `src/26.1` for what differs (GUI drawing, input events, world creation); plain renames as rename
  rules in `stonecutter.gradle.kts` with the release that introduced them.
- [x] Every feature done before the port works on both new nodes: tests green, play tests green.
- [x] The shared code (`src/main`) changes only where a `//? if` or rename is the simplest correct form.
- [ ] Release `2.0.0` with jars for all four nodes.

## Design

- Expected changes, from Blockpilot and Glowline's 26.1 ports: `GuiGraphics` became `GuiGraphicsExtractor`
  (`drawString` → `text`), `ResourceLocation` became `Identifier` (from 1.21.11), game rules became a registry
  (from 1.21.11), the level's day time moved to clocks (`getDayTime` → `getOverworldClockTime`).

## What the port did

- Nodes: Minecraft 26.1.2 on Java 25, NeoForge 26.1.2.124 and Fabric Loader 0.20.0 (accepting 0.18.4 on), Fabric API
  0.155.3 in the dev client only, as Blockpilot's 26.1 nodes have them; the jars are named for 26.1.2. A node marked
  `fabric_gametest_api=true` compiles its GameTests against Fabric API's own annotation, as from 1.21.5.
- Version trees `src/1.21.1` and `src/26.1`, one copy of each class per tree, for what differs throughout:
  - `client/gui/GameScreen`, new: the one class extending the game's `Screen`, turning each version's callbacks (26.1's
    MouseButtonEvent, KeyEvent, CharacterEvent and extractRenderState) into plain calls `FlatgenScreen`, still in
    `src/main` with all its logic, answers; on 26.1 it reads Shift, Control (Command on macOS) and Alt from the window,
    as `Screen` no longer does.
  - `mc/BlockModels`, new: a block's north faces and particle sprite from 1.21.1's baked models or 26.1's block state
    models, quad materials and tint sources.
  - `mc/GameRuleValues`: 26.1 keeps game rules in a registry under new ids; the option format's 1.21.1 names are turned
    into them by the table the game's own update of old worlds uses, three switches inverted ("disableRaids" became
    "raids") and `doFireTick` turned into the fire spread radius (off is 0, on the default), and a rule goes by its old
    name, its id and its short id alike, so an option may name it either way. `GameRuleAccess`, what both share, stays
    in `src/main`.
- `src/main` with `//? if` blocks where a few lines differ: `McCanvas` (sprites drawn through a pipeline; what is drawn
  over an item starts a layer of its own on 26.1, where items are drawn after the rest of a layer, rather than being
  lifted toward the player; tooltips handed over for the frame), `BlockSides` (the tinted blit), `Biomes` (weighted mob
  spawns, the sky colour as an environment attribute over the overworld's), the new `mc/Overworld` (the time of day on
  the dimension's clock from 26.1, the spawn in respawn data from 1.21.11; shared by first-start effects and the
  GameTests), `Exports` (pack formats with minor versions), `WorldCreation.openWithWorldType`, and the GameTests' glue,
  failure, precipitation and a check of 26.1's own game rules.
- Rename rules: `ResourceLocation` to `Identifier`, `ResourceKey.location()` to `identifier()` and the game rules'
  package (1.21.11); `getMinBuildHeight()` to `getMinY()` and `MobSpawnType` to `EntitySpawnReason` (1.21.2);
  `GuiGraphics` to `GuiGraphicsExtractor` with `drawString`, `renderOutline` and `renderItem` to `text`, `outline` and
  `item`, `Util`'s package, `Minecraft.tell` to `schedule` and `getBlockHolder()` to `typeHolder()` (26.1). A rule's new
  text must not appear in shared code, as Stonecutter turns it back for older nodes: a registry lookup common to both
  now reads the same on each.
- Facts: from 1.21.2 the game cools a world with height from 17 above its sea level, which a superflat world keeps at Y
  -63, rather than from Y 80, so on 26.1 snow starts far lower; the biome's climate carries its cooling start, as
  `mc/Biomes` reckons it for the version (F08).
- Datapacks (F21): from data pack format 82 the game reads the formats a pack takes as a range, so 26.1's `pack.mcmeta`
  names `min_format` (the resource format, 84) to `max_format` (the data format, 101.1).

## Tests

- `./gradlew build` on all nodes; play tests on the 26.1 nodes.

## Tried

2026-11-19: `./gradlew build` passes on all four nodes, the 24 GameTests passing on both 26.1 nodes, and `node
tools/boot.mjs 26.1-neoforge 26.1-fabric` booted each jar on its servers (NeoForge 26.1.2.124, Fabric Loader 0.20.0 and
0.18.4). NeoForge 26.1 dev client: Customize opened the editor, drawn as on 1.21.1; the biome and block pickers, the
structures screen, the library and the templates; dragging a layer's edge, the wheel and Shift with it, typing umlauts
in a field; the Nether made flat and a world created whose overworld and Nether had exactly the editor's layers, with a
fortress `/locate` found. Fabric 26.1: the editor and its tabs, the End made flat and saved, its datapack (`min_format`
84, `max_format` [101, 1]) loaded by a vanilla 26.1.2 server with `level-type=flatgen\:end_test` into a world of the
preset's overworld and End, and its server lines making the overworld on another. Not tried on 26.1: the narrator, the
default preset on choosing Superflat, the game's own editor button, and first-start effects in a played world (the
GameTests cover them).

After the port's review: the drawing back in `src/main` with renames and `//? if` blocks, the game rules by any of
their names and `doFireTick` as the fire spread radius, checked against 26.1's own rules by a GameTest; the build
passes on all four nodes with 24 GameTests each, and the editor and the library drew as before on Fabric 26.1 and
NeoForge 1.21.1.
